# Implementation Plan: Guarded, Token-Efficient Office Structured Editing

> Generated by pact-codex-plan-mode on 2026-07-28
> Status: IMPLEMENTED - dependency-pinned CI and manual Office/sync release gates pending

## Summary

Extend `agw office` with generic, token-efficient Excel named-table operations and localized, block-oriented Word editing. The new commands will not form a parallel Office subsystem: every write, including legacy Office commands, will use one shared Guardrails transaction executor for profile and conflict preflight, optional caller hash validation, staged mutation, candidate validation, one verified pre-image archive action, atomic publication, and privacy-safe recovery tracking.

The Excel API is schema-agnostic. Project, client, order, and ID names are examples only and create no built-in columns or business rules. The Word API targets general document editing--headings, paragraphs, and list items--not Word table management.

## Goals

- Report actual populated Excel bounds rather than formatting-inflated worksheet dimensions.
- Discover sheets, used ranges, named tables, table ranges, headers, merged ranges, and defined names.
- Read only the table rows and columns an agent needs, using bounded compact JSON.
- Append and update table rows while expanding table references, preserving styles, and filling calculated columns.
- Support native JSON types and safe, column-aware ISO date coercion.
- Provide compact Word outlines, narrow block reads, and atomic multi-operation localized patches.
- Make every Office write recoverable through the existing Guardrails archive and tracking architecture.
- Retain existing Office commands while migrating them onto the new guarded transaction path.
- Refuse ambiguous, stale, unsupported, lossy, or conflicting operations before changing the live file.

## Non-Goals

- No business-specific schema or client-management logic.
- No pandas dependency or spreadsheet query language.
- No formula calculation engine.
- No arbitrary raw OOXML API.
- No native Word Track Changes in v1.
- No general Word table-cell editing in v1.
- No editing Word headers, footers, comments, footnotes, text boxes, tracked revisions, or nested content in v1.
- No `.xlsm` mutation in v1; read-only inspection may be supported.
- No second general event ledger containing document contents or command payloads.
- No claim of perfect round-trip fidelity for every Office extension or embedded object.

## Agreed Product Principles

1. Generic by construction: commands operate on runtime workbook/document structure.
2. Compact by default: agents receive narrow, bounded results, not complete document dumps.
3. Semantic writes: inputs name columns, rows, or Word blocks rather than raw cell/XML details.
4. One transaction boundary: all Office writes inherit the same archive, conflict, atomicity, and recovery behavior.
5. One logical pre-image per operation: a multi-cell or multi-block edit makes one archive request and one mutation receipt; physical archive bytes may deduplicate.
6. Validate before archiving: routine request, selector, ambiguity, and no-op failures create no archive version.
7. No partial publication: the complete Office package is atomically replaced or the live source remains unchanged.
8. Privacy-minimal tracking: durable records contain hashes, counts, operation category, and recovery identifiers--not cell values, formulas, Word text, or payloads.

#### Component Boundaries

Keep `office.py` as the compatibility facade rather than converting it into a package:

~~~text
agw.py
  -> office.py
       -> office_excel.py
       -> office_word.py
       -> office_tx.py
            -> store/archive transactions
            -> profiles/checkouts/locks
            -> atomic publication and receipts
~~~

Adapters never archive, lock, replace a live file, or write recovery records. The transaction executor knows nothing about Excel tables or Word paragraphs; it accepts immutable plans plus apply and validate callbacks.

#### Transaction Invariants

Every mutation must satisfy:

- The target is a regular supported local file, not a placeholder, Office owner file, conflict artifact, symlink, junction, or unsupported reparse target.
- No direct mutation proceeds while the source has an open CRUA checkout.
- A canonical per-target Guardrails lock is held from first hash through receipt commit.
- The plan is complete and immutable before archiving or changing the live source.
- Dry-run creates no archive, candidate residue, receipt, or source metadata change.
- The staged candidate is exclusively created in the verified target directory with the same extension and permissions no broader than the source.
- The candidate reopens and satisfies operation-specific postconditions.
- Live source identity and hash match the planned source immediately before archiving and replacement.
- The archive artifact hash equals the bytes being replaced.
- Publication uses same-directory `os.replace` with no copy-over fallback.
- Every success has one verified pre-image reference and one committed privacy-safe receipt.
- A crash after replacement is discoverable through a prepared mutation manifest.

Recommended sequence:

~~~text
acquire canonical target lock
-> profile, checkout, link, lock-artifact, and package preflight
-> hash source H0 and enforce optional caller hash
-> resolve selectors and build immutable mutation plan
-> if dry-run, return bounded preview
-> create same-directory staged copy
-> apply plan only to stage
-> reopen and validate stage; calculate Hnew
-> verify live identity/hash still H0
-> archive live pre-image; verify archive hash equals H0
-> persist privacy-safe prepared mutation manifest
-> verify live identity/hash still H0
-> atomically replace stage over live
-> verify live hash equals Hnew
-> mark mutation receipt committed
-> release lock
~~~

Building and validating the stage before archiving avoids archive noise from serialization failures while still ensuring the pre-image exists before the live file is touched.

Conceptual interface:

~~~python
execute_mutation(
    path,
    operation,
    expected_sha256=None,
    plan=plan_callback,
    apply=apply_callback,
    validate=validate_callback,
    dry_run=False,
)
~~~

Conflict errors use exit code `3`, missing optional libraries use `2`, and request/validation errors use `1`.

#### Tracking Contract

A successful Office mutation record links to the existing archive transaction:

~~~json
{"op":"office-mutation","mutation_id":"...","operation":"update-table-row","before_sha256":"...","after_sha256":"...","snapshot_transaction_id":"...","snapshot_version":4,"affected":1,"state":"committed"}
~~~

The record must not contain cell values, formulas, filters, Word text, replacement text, snippets, or raw payloads. Prepared manifests exist for recovery coordination, not as a new command-history product. `agw status` and `agw doctor` surface incomplete transactions; `agw restore <file>` remains the recovery mechanism.

#### Key Decisions

| Decision | Recommendation | Rationale |
|----------|----------------|-----------|
| Module layout | Sibling modules with `office.py` facade | Clear boundaries without import/package churn |
| Expected hash | Optional for Excel and legacy writes; required for Word block patches | Matches requested optional precondition while block IDs remain version-bound |
| Stage/archive order | Validate stage, then archive immediately before replacement | Avoids archive noise and still snapshots before live mutation |
| Tracking | Privacy-safe receipt linked to existing recovery metadata | Durable recovery without content-bearing surveillance |
| Excel formats | `.xlsx` writes only in v1 | Prevent macro stripping |
| Word identity | Opaque block ID plus whole-file hash | Compact and unambiguous for one version |
| String coercion | Preserve strings; column-aware ISO dates; explicit formulas | Protect identifiers and prevent formula injection |
| Formula filling | Translate only verified calculated-column patterns | Avoid guessing |
| Legacy commands | Retain and migrate to shared executor | Compatibility with one safety standard |
| Word scope | Top-level body blocks with explicit exclusions | Useful localized editing with honest fidelity limits |

## Public CLI and Output Contracts

### Shared Conventions

- Preserve `agw office <operation> <file>`.
- Replace the flat Office parser with operation-specific subparsers.
- Use concise human output and compact, non-indented `--json`.
- Reads return `hash` for optional or required write preconditions.
- Inline and file payload flags are mutually exclusive.
- Reject duplicate JSON keys, unknown fields, non-finite numbers, excessive nesting, and oversized payloads.
- Writes return counts and recovery identifiers, not complete modified data.
- Default previews are bounded; detail is opt-in.

### Excel Discovery

~~~text
agw office info workbook.xlsx --json
agw office info workbook.xlsx --scope tables --json
agw office info workbook.xlsx --scope names --json
~~~

Each sheet reports:

- `used_range`, `rows`, `cols`, and `nonempty_cells` based on cells where `cell.value is not None`.
- `worksheet_dimension` as the separate formatting/styled extent.
- Named tables with sheet, name, reference, headers, totals state, and row count.
- Merged ranges and other relevant ranges.
- Workbook- and worksheet-scoped defined names, including unresolved/dynamic status.

Formula cells and stored empty strings count as populated; `None` does not. Dynamic, external, multi-area, full-row, and full-column defined names may be reported but are not mutation targets in v1. Bounds calculation must not iterate through an inflated rectangular maximum.

### Excel Narrow Reads

~~~text
agw office read-table workbook.xlsx --table Orders --json
agw office read-table workbook.xlsx --table Orders --columns ID,Status --where-json '{"Status":"Open"}' --offset 0 --limit 50 --json
~~~

Compact response:

~~~json
{"hash":"...","table":"Orders","sheet":"Data","ref":"A1:D101","headers":["ID","Status"],"rows":[[17,"Open"],[24,"Open"]],"offset":0,"returned":2,"more":false}
~~~

Rules:

- Resolve table names case-insensitively and uniquely across the workbook; allow sheet qualification.
- `--columns` preserves requested order.
- `--where-json` supports equality predicates only in v1.
- Default limit is 50; proposed hard maximum is 500 rows per response.
- Dates serialize as ISO strings; other values retain JSON types.
- Formulas return formula text by default. `--values-only` returns cached values with a stale-cache warning.
- Headers appear once and rows are arrays.

### Excel Append and Update

~~~text
agw office append-table-row workbook.xlsx --table Orders --row-json '{"ID":25,"Status":"Open","Due":"2026-08-01"}' --expected-file-hash <sha256> --dry-run --json

agw office update-table-row workbook.xlsx --table Orders --key-column ID --key 25 --set-json '{"Status":"Closed"}' --expected-file-hash <sha256> --dry-run --json
~~~

`--expected-file-hash` is optional for Excel but recommended after a read. `--row-file` and `--set-file` support large or quoting-sensitive inputs. `--key-json` provides a typed scalar alternative to string `--key`.

All JSON-bearing options accept `-` to read one payload from stdin. This is the
preferred PowerShell form because JSON quotes and spaces do not cross the native
argument boundary, for example:

```powershell
'{"ID":25,"Status":"Needs review","Due":"2026-08-01"}' | agw office append-table-row workbook.xlsx --table Orders --row-json - --json
```

Append rules:

- Input is keyed by actual headers; unknown headers and duplicate JSON keys fail.
- Missing cells are blank unless a verified calculated column fills them.
- Append occurs before a totals row and expands the table reference by one data row.
- Refuse overlap with unrelated populated cells, another table, or merged cells.
- Copy styles and row properties from the prior data row when available.
- Translate formulas only after calculated-column pattern consistency is verified.
- Never infer formulas from a totals row.
- Header-only tables report missing cell-template behavior in dry-run warnings.
- Preserve separate validation/conditional-format ranges without promising automatic expansion in v1.

Update rules:

- Exactly one key match is required; zero or multiple matches fail before archiving.
- Multiple column changes are one transaction, archive request, and receipt.
- Unknown columns, headers/totals, protected cells, and merged targets fail.
- Formula columns require an explicit formula value and passing formula policy.

Structured value rules:

- JSON numbers, booleans, and null retain their types.
- JSON strings remain literal, including numeric-looking identifiers such as `"007"`.
- ISO strings convert only in an established date column or with `--coerce-iso-dates`.
- Offset-aware datetimes are rejected in v1.
- Formulas require an explicit typed object; external-reference formulas are refused by default.
- Legacy commands retain documented coercion semantics for compatibility.

Compact mutation result:

~~~json
{"changed":1,"snapshot":4,"mutation":"...","hash":"..."}
~~~

Compact dry-run result:

~~~json
{"dry_run":true,"changed":1,"table":"Orders","old_ref":"A1:D101","new_ref":"A1:D102","warnings":[],"hash":"..."}
~~~

### Word Outline, Reads, and Patch

~~~text
agw office outline report.docx --offset 0 --limit 50 --json
agw office read-blocks report.docx --ids p12-a91c,p13-b72d --json
~~~

Compact outline:

~~~json
{"hash":"...","blocks":[["p1-a91c","h1","Overview"],["p2-b72d","p","Opening text..."]],"offset":0,"returned":2,"more":false}
~~~

Block IDs are opaque locators derived from original document order, type, and a compact content fingerprint. They are valid only with the returned whole-file hash. Default snippets are capped at 160 characters; full selected text comes from `read-blocks`.

V1 editable blocks are top-level body headings, paragraphs, and list paragraphs. Top-level tables may appear as non-editable anchor blocks. Unsupported parts are reported or counted and never silently exposed as editable.

~~~text
agw office patch report.docx --expected-file-hash <sha256> --ops-file patch.json --dry-run --json
~~~

`--ops-json` supports short inline patches. V1 operations are `replace_text`, `replace_block`, `insert_before`, `insert_after`, `append`, and `delete_block`. Every block resolves against the original before any edit is applied; one stale or unsupported target rejects the whole patch.

Formatting contract:

- Local text replacement preserves unaffected runs and paragraph style.
- Whole-block replacement preserves paragraph style if no style is provided.
- Inserted blocks use named Word styles.
- Whole-block replacement does not promise arbitrary inline run, field, hyperlink, bookmark, revision, or embedded-object fidelity.
- Signed or known-lossy documents are refused.
- Whole-document rewriting remains a CRUA checkout/publish task.

### Failure-Injection Boundaries

Inject failures at parsing, initial hash, stage creation, adapter save, stage reopen, postcondition validation, archive publication, archive verification, final source rehash, prepared-manifest persistence, atomic replace, final hash, and receipt commit.

At every boundary assert:

- Live source is exact old bytes or exact validated new bytes.
- External source changes are never overwritten.
- No copy fallback occurs.
- Every success has a verified pre-image and committed receipt.
- Prepared-but-incomplete states are visible to recovery/status.
- Only transaction-owned staged artifacts may be cleaned automatically.

- Duplicate/unknown JSON keys and bounded payloads.

- Sanitized errors and receipts without document content.

## Alignment Decisions

Approval of this plan approves these defaults:

1. Excel and legacy `--expected-file-hash` remains optional; Word block patch hashes are required.
2. Structured table JSON preserves strings, performs column-aware ISO date conversion, and requires explicit formulas.
3. Only `.xlsx` mutations ship in v1; `.xlsm` writes are refused.
4. Word v1 edits top-level body headings, paragraphs, and list items; it does not implement Track Changes or general table-cell editing.
5. Mutation receipts extend existing recovery metadata and never include document contents or raw payloads.
6. Existing Office write commands remain public and migrate to the transaction executor before new mutation commands ship.
7. Separate validation/conditional-format ranges are not auto-expanded unless preparation proves a safe general rule.
8. No `--force` bypass is added for hash, identity, selector, or source-drift conflicts.
